# ADR-008 — M2a speech: Android on-device recognizer and TTS, push-to-talk identity

**Status:** Accepted for M2a (code). **Device verification pending**: airplane-mode recognition, offline speech pack detection, offline TTS voice, microphone revoke.

## Context
M2a (docs/11 C2) needs speech-to-text, spoken replies and a dialogue, without cloud processing (CLAUDE.md, Z-028) and without bundling model weights whose licence we have not checked (docs/08).

Options for speech-to-text:
1. Bundle Vosk / whisper.cpp / sherpa-onnx with a downloaded model. This needs a licensed model sideloaded by the owner, a native runtime, and a benchmark on the Pixel.
2. Android's **on-device** recognizer: `SpeechRecognizer.createOnDeviceSpeechRecognizer` (API 31+), with `checkRecognitionSupport` reporting which languages are installed for offline use. Pixel phones ship this with downloadable offline language packs.

## Decision
1. **Speech-to-text:** use `createOnDeviceSpeechRecognizer` only. Zeno never uses the default `createSpeechRecognizer` (which may be cloud-backed). Before offering the mic, Zeno checks `installedOnDeviceLanguages` for `en-US`; if it is missing, the mic stays disabled and the owner is told how to install the offline pack in Android Settings. Zeno never triggers a model download itself. Network-type recognizer errors are reported as "tried to use the network, which Zeno doesn't allow".
2. **Text-to-speech:** Android `TextToSpeech` with the installed engine, using only a voice with `isNetworkConnectionRequired == false`. Without one, replies are text only. Zeno bundles no voice.
3. **Ports stay replaceable:** `SpeechInput` and `Speaker` are interfaces. A bundled engine (Vosk, sherpa-onnx) can be added later through the model manifest (`docs/MODEL_INSTALL.md`) without touching the parser, policy or dialogue. M2b's wake word and speaker verification will need such a bundled runtime anyway (ADR-007).
4. **Microphone use:** `RECORD_AUDIO` is requested only when the owner first taps the mic. One tap = one utterance; the recognizer is destroyed after the result, error or cancel. No background capture, no foreground service, no audio stored by Zeno. "Listening…" is shown only while a recognition session is open.
5. **Identity for push-to-talk:** a new `CommandSource.PUSH_TO_TALK`. There is no speaker verification in M2a. The owner's Android unlock is the identity check: while the phone is locked, every push-to-talk command except stop/cancel returns `RequireDeviceCredential`. Voice is never treated as authentication (Z-016). Typed commands use the same source and the same policy.
6. **Honest scope:** commands are parsed (rule-based parser, `docs/03` fixtures) and checked by policy. Only "stop listening" has an action adapter in M2a. Any other understood command is explained with the milestone that builds it ("Nothing was sent / No call was made / Nothing was changed") and is never offered for confirmation.

## Consequences
- Offline speech depends on Google's on-device recognizer and its offline pack being installed. That is a dependency on a system component, not on a network service. It must be verified in airplane mode on the Pixel (pending).
- The transcript is kept in memory only (last 30 lines) and cleared when the app process ends.
- Speech accuracy is not under Zeno's control in M2a; the parser is measured separately (held-out phrasing accuracy 88 %, 35/40, every miss is "not understood", never a different command).
- Play Store: `RECORD_AUDIO` with a visible, user-initiated mic is a normal use. Sideloading is the target (ADR-006).
