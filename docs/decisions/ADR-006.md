# ADR-006 — Toolchain, SDK levels and module layout

**Status:** Accepted (M0, 2026-11-21).

## Decision
- **Build:** Gradle wrapper 9.9.0, Android Gradle Plugin 9.5.1 (built-in Kotlin), Kotlin 2.4.21, Compose BOM 2026.09.00, Material 3. Versions match what was already cached on the development PC so builds are reproducible offline once dependencies are downloaded.
- **JDK:** run Gradle with Android Studio's bundled JBR (JDK 25). The system Java 27 is not used for builds. Bytecode targets Java 17.
- **SDK levels:** `minSdk = 34`, `targetSdk = 34`, `compileSdk = 37`. The only target device (Pixel 4a 5G, `bramble`) receives no updates beyond Android 14, so targeting 34 keeps runtime behaviour identical to what we test. `compileSdk` 37 is simply the installed platform.
- **Modules** (resolves review conflict C1 in favour of the v2 docs, kept small):
  - `:app` — Compose UI and, later, Android adapters. **No permissions in M0; never INTERNET** (enforced by `ManifestPolicyTest`).
  - `:core:domain` — pure Kotlin/JVM contracts: intents, policy, voice state machine, action routing, root allowlist, routine model, scheduling rules. No Android dependency, so the safety rules are unit-tested on the JVM.
  - `:core:testing` — fakes shared by tests. Never a production dependency.
  - `:spike` — separate debug APK (`com.zeno.spike`) for device feasibility spikes, so its microphone/boot permissions never leak into `:app`.
  - Further modules (`core:data`, `core:voice`, `feature:*`) are split out only when a milestone needs them.
- **Gradle files at the repository root**, as in `docs/FILE_TREE.md`. The `Archtecture/` v1 folder is superseded and kept unchanged until the owner approves archiving it.
- **JVM UI tests:** Robolectric runtime SDK 35 (already cached). Device behaviour is verified only on the real phone.

## Consequences
- `local.properties` (SDK path) is machine-local and git-ignored; Android Studio creates it automatically.
- Command line: set `JAVA_HOME` to `C:\Program Files\Android\Android Studio\jbr` before running `gradlew.bat`.
- Moving to Google Play distribution would require revisiting `targetSdk` and SMS/Call-Log policy (docs/06).
