# ADR-009 — Wake-word and speaker-verification engine (decision needed)

**Status:** **Proposed — waiting for the owner's decision.** M2b part 1 (engine-independent code) is built. Part 2 (engine adapters, listening foreground service) starts once this is decided and the owner has installed the chosen models.

## Context
ADR-007 settled the architecture (default assistant + microphone foreground service running Zeno's own wake-word model) and asked for a benchmark before choosing an engine. M2b also needs an on-device **speaker embedding** model for owner verification (Z-005, docs/08). Constraints: no cloud, no licence check that phones home, licence-checked model files installed by the owner (Zeno never downloads them), verifiable official distributions, Android arm64.

What is engine-independent and already built (ports in `core/domain`):
- `WakeWordDetector` (scores per frame) + `WakeScoreFilter` (threshold, patience, refractory, ignore own TTS).
- `SpeakerEmbedder` (clip → embedding) + enrollment, verifier, replay guard, calibration (FAR/FRR/EER).
- `WakePipeline`: wake → capture → owner check → hand-off, with no transcription of unverified speech.

## Options
| | A. sherpa-onnx (k2-fsa) | B. ONNX Runtime + openWakeWord + separate speaker model | C. Picovoice Porcupine/Eagle |
|---|---|---|---|
| Code licence | Apache-2.0 | ONNX Runtime MIT; openWakeWord Apache-2.0 | Proprietary SDK |
| Wake word | Open-vocabulary keyword spotting: a typed phrase works **without training** (helps Z-001) | Needs a trained "Hey Zeno" head (PC training step). Official pretrained phrase heads are CC BY-NC-SA 4.0 (personal use only); the shared feature models are Apache-2.0 | Custom phrase needs their console |
| Speaker verification | Same runtime ships speaker-embedding support | Separate model; Zeno must implement its feature front-end (fbank) | Eagle, same licence issue |
| Android packaging | Official Android builds exist; the exact artifact and version must be verified at implementation time (not confirmed yet) | `onnxruntime-android` is on Maven Central | AccessKey + licence validation; offline use unclear |
| Components to maintain | 1 runtime | 2–3 pieces + our own feature code | 1 SDK |
| Main risk | CPU/battery of open-vocabulary spotting; model licences vary per file | More custom code; NC licence on ready-made phrase models | Not acceptable under "no remote licence check" unless proven offline |

## Recommendation
**A (sherpa-onnx)**, subject to **SPIKE-04** on the Pixel before it becomes the default:
- keyword spotting with "Hey Zeno": detections and false wakes per hour (TV/talk radio), CPU %, 30-minute battery drain, screen off;
- speaker embedding: owner vs 3+ consenting non-owners and phone playback, giving FAR/FRR/EER with `Calibration`;
- memory (PSS) for wake standby and for verification.

If SPIKE-04 fails on battery or false wakes, fall back to B with a self-trained head.

## What the owner needs to decide
1. Approve option A (or choose B/C).
2. Approve downloading the official model files and runtime from the project's own release pages to your PC, then installing them with `adb push` (docs/MODEL_INSTALL.md). Zeno itself never downloads anything. Each file's URL, licence, SHA-256 and size go into the model manifest and this ADR before use.
3. Personal use only, or possible publication? (It changes which model licences are acceptable.)

## Consequences
- Until decided: Zeno shows "Wake-word engine not installed", voice training says no speaker model is installed, and nothing is recorded except push-to-talk.
- The decision does not change the domain code: only adapters behind `WakeWordDetector` and `SpeakerEmbedder`.
