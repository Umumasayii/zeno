# ADR-007 — Wake-word strategy for a sideloaded assistant

**Status:** Proposed. **Architecture path confirmed on device by SPIKE-01/02 (2026-11-21)**: the assistant role is selectable, system hotword permission is refused, and a microphone FGS started from the assistant service keeps real audio with the screen off and locked, including about 5 s after first unlock following a reboot. Still pending: wake-word engine benchmark and long-duration battery test.

## Context
ADR-002 prefers Android's `VoiceInteractionService` (default assistant) for always-on listening. The official hotword paths for assistants are `AlwaysOnHotwordDetector` (DSP) and `HotwordDetectionService` / `createHotwordDetector` (sandboxed software hotword).

**Desk finding (M0, compile time):** In the public SDK (compileSdk 37), `createAlwaysOnHotwordDetector`, `createHotwordDetector`, `AlwaysOnHotwordDetector`, `HotwordDetector` and `HotwordDetectionService` are `@SystemApi` and cannot be used by a normal app. The spike module failed to compile against them and now probes their runtime visibility by reflection instead. Expectation (to confirm on device): a sideloaded Zeno can be the default assistant, but cannot use the system hotword pipeline.

## Decision (proposed)
1. **Primary path:** a microphone foreground service (type `microphone`) running Zeno's own small wake-word model, started while Zeno is visible or by an allowed trigger. The persistent notification and Android's green microphone indicator are visible by design. Android may still stop or silence it; the UI must report that honestly (Z-029).
2. **Wake-word engine:** benchmark on the Pixel before choosing:
   - *openWakeWord*: train "Hey Zeno" once on the PC. Code Apache-2.0; pretrained model licences must be checked (some are non-commercial, acceptable for personal use only).
   - *sherpa-onnx keyword spotting*: open-vocabulary keywords without training (helps Z-001's custom wake word), higher CPU cost. The same runtime offers speaker embeddings and ASR.
   - *Porcupine*: excluded unless its licence check can run fully offline (to verify).
3. **Optional root upgrade (M7+):** install Zeno as a privileged system app through a Magisk module. That might unlock the system hotword APIs (needs a separate spike, and building against system API stubs). Never required for core use.
4. Keep `VoiceInteractionService` for assistant-gesture invocation and the session UI if SPIKE-01 shows the role is selectable.

## Consequences
- "Always listening" is best-effort and visibly indicated. That matches CLAUDE.md: never covertly defeat OS privacy controls.
- Battery target NFR-03 must be measured with the foreground-service design.
